## Donor A — Linux 4.19.325 (primary device reference)

Repository: https://github.com/isabe8499-oss/kernel_motorola_msm8953-22  
Branch: `4.19.325-WIP`  
Audited branch tip: `b7ef28b2acd6a61a4d890b87e57e0d5de6c93c4e`

Verified files and hardware data:

- Deen config: `arch/arm64/configs/vendor/deen_defconfig` (blob `ecef3b19eb5cbe5fef0c343b8fee2d54071a3c37`).
- Build driver: `build.sh`; it supports local reuse of a Clang toolchain and has separate device-tree and ZIP options.
- Board DTS files are at `arch/arm64/boot/dts/vendor/qcom/motorola/msm8953-deen-pvt1.dts` and `msm8953-deen-pvt2.dts`.
- Shared board file: `arch/arm64/boot/dts/vendor/qcom/motorola/deen/deen.dtsi` (blob `7b551b4067bad7ac83d68ff979ac6d84cd11db08`).
- PVT1 board ID: `<0x4D 0xC100>`; PVT2 board ID: `<0x4D 0xC200>`. The XT1941-3 model number alone does not establish which board ID is in the handset.
- The Deen DTS includes Android, audio, battery, camera, display, fingerprint, GPU, NFC, pinctrl, PMI8950, regulators, reserved memory, sensors, storage, thermal, touchscreen and vibrator fragments.
- Touchscreen DTS defines Novatek NVT at I2C 0x62 and FocalTech FT8006U at I2C 0x38. The Novatek node uses reset GPIO64 and IRQ GPIO65; the FocalTech node also uses GPIO64/65 and specifies 720x1520.
- Display fragment references Tianma and Nova 720p panels.
- The donor has the Qualcomm KGSL implementation under `drivers/gpu/msm/`, including `QCOM_KGSL` Kconfig wiring.
- Camera-v2 implementation is under `drivers/media/platform/msm/camera_v2/`; the tree also has `techpack/camera-legacy/Kconfig`.
- Deen defconfig includes `ARCH_MSM8953`, Deen machine support and Qualcomm platform components.

The donor has another branch, `bakasu-susfs23-deen`, containing SUSFS/NoMount changes. It is not the selected donor. Only the clean `4.19.325-WIP` branch is used for this baseline.

### ACK coverage already present

- `drivers/clk/qcom/gcc-msm8953.c`, Kconfig `MSM_GCC_8953`, Makefile wiring.
- `drivers/pinctrl/qcom/pinctrl-msm8953.c`, Kconfig `PINCTRL_MSM8953`, Makefile wiring.

- Qualcomm SMD RPM driver: `drivers/soc/qcom/smd-rpm.c`.
- Generic FocalTech FT5x06 touchscreen support exists, but it is not proof of FT8006U compatibility.

### Confirmed gaps in the pinned ACK tree

- No `arch/arm64/boot/dts/qcom/msm8953.dtsi` was found.
- The ACK `arch/arm64/boot/dts/qcom/Makefile` has no MSM8953 Deen board DTB entry.
- No `drivers/gpu/msm/Kconfig` / KGSL tree was found in the pinned ACK source.
- No `techpack/camera-legacy/Kconfig` or legacy MSM camera-v2 tree was found in the pinned ACK source.
- The ACK source has a mainline DRM/MSM path, but DRM is not a drop-in substitute for the vendor KGSL userspace ABI.

These findings mean the SoC controller drivers can be reused, but the Deen board DTS and several Android vendor hardware stacks still require a controlled port.

## Source-integrity policy

- Record source URL, branch, exact commit, blob/path and license for every imported component.
- Prefer ACK implementations when a compatible implementation already exists.
- Port only the required device files and dependencies; do not copy an entire vendor driver tree without API/Kconfig review.
- Keep each workstream isolated in reviewable commits.
- Do not import build outputs, private signing keys, device secrets, generated vendor blobs, SUSFS, NoMount, KernelSU, BakaSU or Magisk into the clean baseline.
